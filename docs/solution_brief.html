Solution Brief · Embedded CI

실물 보드 없이, QEMU로 라즈베리파이4 이미지를 돌리는 자동테스트 파이프라인

보드용 Yocto 이미지를 그대로 QEMU에 부팅하고, 앱 바이너리만 교체해 회귀 테스트를 자동화한다. 개발 피드백 루프에서 물리 보드 의존을 걷어내는 것이 목표다.

01 배경 & 목표

왜 필요한가

임베디드 개발은 코드를 고칠 때마다 실물 보드에 플래싱하고 손으로 확인해야 한다. 보드 수가 한정되고, 플래싱·부팅이 느리며, 병렬 테스트와 CI 자동화가 어렵다. 앱 로직 수준의 회귀는 대부분 하드웨어가 아니라 유저스페이스에서 잡히는데도, 매번 보드를 붙잡는다.

문제
  • 수정 → 플래싱 → 수동 확인의 느린 루프
  • 보드 대수 제약으로 병렬·야간 테스트 불가
  • PR마다 자동 회귀 검증이 없음
  • 유저스페이스 버그도 보드에서만 확인
목표
  • 보드 이미지를 QEMU에서 그대로 부팅
  • 이미지 재빌드 없이 앱 바이너리만 교체
  • 부팅→테스트→결과회수를 한 명령으로
  • CI에 붙여 PR마다 자동 회귀
02 설계도 · 시스템 아키텍처

구성 요소와 격리 계층

낡은 호스트(Ubuntu 16.04 / Python 3.5)를 건드리지 않도록 빌드·실행을 Docker로 격리한다. QEMU는 -M virt 범용 머신에 보드 rootfs와 virtio를 켠 커널을 올리고, 호스트와 게스트는 9p 파일 공유로 이어 바이너리와 결과를 주고받는다.

04 설계도 · 테스트 실행 플로우

한 명령이 하는 일

bash poc/run-poc.sh 하나로 아래 순서가 자동 실행된다. 사람이 개입하는 지점은 오직 바이너리를 testshare/에 넣는 것뿐이다.

바이너리 배치

cp myapp poc/testshare/ — 교체 대상은 이 폴더 하나. 이미지 재빌드 없음.

QEMU 부팅

보드 커널 + rootfs를 -M virt로 기동. 시리얼 콘솔(ttyAMA0)로 로그인 프롬프트까지 진행.

자동 로그인

expect가 root@raspberrypi4-64 셸에 진입(무비번).

9p 마운트

호스트 testshare/를 게스트 /mnt/host에 연결.

테스트 실행

run-tests.sh가 앱 바이너리를 실행하고 출력을 result.txt에 기록.

결과 회수 & 종료

result.txt가 9p로 호스트에 즉시 남고, poweroff로 깨끗이 종료.

06 커버리지 층위

어디까지 QEMU로, 어디부터 보드로

테스트는 유저스페이스만이 아니라 커널 레벨도 있다. 중요한 점: 이 환경은 실제 라즈베리파이4 커널(5.15.92)을 그대로 QEMU에 올린다 — 다만 부팅 머신(-M virt vs raspi4b)에 따라 커널의 어느 계층까지 실제로 실행되는지가 갈린다. 아래는 그 사다리다.

에뮬 불가 · 실물 보드 전용

실물 보드

T1·T2는 오늘 CI로 자동화 가능(회귀의 대부분). T3도 실증 완료 — QEMU 9.x의 raspi4b(mainline, 패치 불필요)로 실제 Pi4 커널+보드 DTB가 로그인까지 부팅했고 BCM2711 드라이버(mailbox·DMA·GPIO·mmc)가 실제로 probe됐다. 미에뮬 주변장치(GPU·카메라·genet 이더넷·PCIe)는 커널이 우아하게 degrade한다. T4만 실물 보드로 남긴다. 즉 대체가 아니라, 커널까지 끌어올린 보완이다.
